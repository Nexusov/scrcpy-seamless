# Architecture decision records

Use an ADR when a durable architecture or repository policy decision has
meaningful tradeoffs. Do not use ADRs for routine implementation details. The
[target architecture](../architecture/SEAMLESS_2_TARGET.md) describes the
current plan; an accepted ADR can refine it, and supersession must be explicit.

Create records as `NNNN-short-title.md`, starting at `0001`, using the
[template](template.md). Give each record a status: Proposed, Accepted,
Superseded, or Rejected. A proposed record is not project policy. Record the
decision date, context, considered alternatives, consequences, and links to
superseding records where applicable. Add each new record to this index.
